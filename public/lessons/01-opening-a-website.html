Life of a request

You type an address and a page appears. Behind that one second, four things happen. Let's walk through them.

A request is a round trip. A name has to become an address before anything can be sent, and every hop on the way adds latency.

Press Next step to type shop.com into your browser.

The four steps, in words

  1. Look up the address. Computers find each other by number (an IP address), not by name. DNS is the contacts list that turns shop.com into a number.
  2. Send the request. Your browser posts a short note to that number: "please send me the home page".
  3. The server does its work. A server is just a computer that's always on, waiting for notes like yours. It gathers the page.
  4. The reply comes back. The page travels back and your browser draws it.
In a design review "The client resolves the domain through DNS, opens a connection to the server, sends an HTTP request, and the server returns a response."
