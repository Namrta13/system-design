Load balancer: sharing the work

One server can only serve so many people at once. When too many show up, it slows down and falls over. The fix is more servers, plus someone to share the visitors out.

Capacity per node is fixed. Past it, queues grow and requests fail. Adding nodes only helps if something distributes traffic across them and stops sending to nodes that are down.

What just happened

With one server, every visitor goes to the same place. Past about 4 a second, its bar goes red and visitors get turned away (in real life: slow pages or errors).

Add two more servers and the host takes turns: A, B, C, A, B, C. This is called round robin. Each server now gets a third of the visitors, so all three stay green.

A bonus: if one server breaks, the host just stops sending people to it. Visitors never notice.

In a design review "I'll put a load balancer in front of several stateless app servers so we can scale horizontally. It uses round robin or least-connections, and health checks remove failed servers."
